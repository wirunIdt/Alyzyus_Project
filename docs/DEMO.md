# ทดลอง Alyzyus สำหรับ Portfolio

เปิด `https://alyzyus.vercel.app/demo` เพื่อทดลองโดยไม่สมัครบัญชีหรือใช้รหัสผ่านร่วมกัน
หน้าสาธิตใช้สินค้าตัวอย่างที่มากับโครงการ 6 รายการ และออเดอร์สมมติ `DEMO-1001`
การสลับเป็นผู้ดูแลในหน้านี้ใช้เพื่อแสดงกระบวนการ ไม่ให้สิทธิ์ Admin บนระบบจริง

## เส้นทางลองเล่น 2–3 นาที

1. เปิด **ฝั่งลูกค้า** แล้วเพิ่มสินค้าลงถุง กด **สร้างออเดอร์จำลอง**
2. ดูเลขออเดอร์ ยอดสินค้า ค่าจัดส่ง และสถานะเริ่มต้น
3. สลับเป็น **ฝั่งผู้ดูแลจำลอง** แล้วขยับสถานะทีละขั้น
4. ดูเส้นทางออเดอร์ด้านล่างซึ่งเปลี่ยนตามที่กด ไม่มีการเลื่อนสถานะเอง
5. เปิดเรื่อง Customer Service ด้วยข้อความสมมติ ไม่มีทีมงานได้รับข้อความนี้
6. กด **เริ่มตัวอย่างใหม่** หรือรีเฟรชหน้าเพื่อคืนข้อมูลตั้งต้น

เลือกภาษาไทย อังกฤษ จีน และสลับธีมสว่าง/มืดจากส่วนหัวได้ ไม่ต้องติดตั้งแอป

## ขอบเขตของข้อมูลจำลอง

ข้อมูลถุงสินค้า ออเดอร์ สต็อก และข้อความอยู่เฉพาะในหน่วยความจำของหน้านี้
ไม่มี localStorage, cookie สำหรับเข้าสู่ระบบ, API ที่สร้างออเดอร์, การส่งอีเมล หรือการเรียกเก็บเงินจริง
ข้อมูลหายเมื่อรีเฟรชหรือปิดหน้า กรุณาไม่กรอกข้อมูลส่วนบุคคลจริง
รูปสินค้าเป็นภาพสาธิตสาธารณะ หากบริการรูปไม่พร้อม กระบวนการในหน้ายังทำงานได้

การเปลี่ยนสต็อกและสถานะใน demo เป็นการจำลองฝั่ง browser เพื่ออธิบาย UX
การตัดสต็อกแบบ transaction, row lock, idempotency และสิทธิ์ RLS ของระบบจริงอยู่ใน PostgreSQL
อย่าใช้ผลการลอง demo เป็นหลักฐานว่าทดสอบระบบชำระเงินจริงหรือการสั่งซื้อพร้อมกันแล้ว

## เมื่อบริการฐานข้อมูลชั่วคราวไม่พร้อม

หน้า `/demo` ไม่เรียก Auth หรือฐานข้อมูล จึงยังใช้สาธิตได้โดยไม่ขึ้นกับการเชื่อมต่อ Supabase
หน้า public catalog ใช้ข้อมูลตัวอย่างแบบอ่านอย่างเดียวเมื่อ provider ตอบผิดพลาด
ผลลัพธ์มี `configured: false`, `catalogFallback: true` และป้ายแจ้งว่าเป็นตัวอย่าง
หน้าชำระเงินจะไม่เปิดให้สั่งซื้อจากข้อมูลสำรองนี้
การ fallback ไม่เปิดสิทธิ์ Admin ไม่ยืนยันบัญชี และไม่เปลี่ยน API ส่วนตัวให้ใช้ข้อมูลจำลอง
หาก catalog จริงไม่มีสินค้า ระบบแสดงรายการว่างตามข้อมูล ไม่เติมสินค้าสมมติแทน
ข้อผิดพลาดของ API ส่วนตัวไม่เปลี่ยนไปใช้ข้อมูล demo และยังต้องผ่านการตรวจสิทธิ์เดิม

โหมดสาธิตช่วยลดการพึ่งพาฐานข้อมูลสำหรับการนำเสนอ แต่ไม่รับประกันว่า hosting หรือ network
จะเปิดได้ตลอดเวลา ควรตรวจลิงก์ก่อนส่ง Portfolio และเก็บ PDF/ภาพหน้าจอประกอบไว้ด้วย

## จุดที่แก้ไข

- `server/demo.py` route สำหรับหน้า demo และเลือกเฉพาะฟิลด์สินค้าสาธารณะ
- `templates/demo.html` โครงหน้าแยกจากระบบบัญชีและถุงสินค้าจริง
- `public/static/js/demo.js` กระบวนการจำลองและข้อความ 3 ภาษา
- `public/static/css/demo.css` หน้าจอ responsive และใช้สีธีมเดียวกับ storefront
- `server/database.py` อ่าน fixture สาธารณะและ fallback เฉพาะ public catalog
- `tests/test_demo.py`, `tests/demo.test.mjs` ตรวจการแยกข้อมูล สิทธิ์ การเริ่มใหม่ และ flow ตัวอย่าง

การเพิ่ม template ต้องเพิ่ม `demo.html` ใน allowlist ของ `scripts/package-vercel.py`
และลงทะเบียน `server.demo.bp` ใน app factory ก่อน deploy
