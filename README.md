# Alyzyus

ร้านค้าออนไลน์สำหรับสินค้าหลายหมวดหมู่ ใช้ **Python + Flask** ฝั่งเซิร์ฟเวอร์ และ **HTML/Jinja2 + CSS + JavaScript ปกติ** ฝั่งหน้าเว็บ ไม่มี React/Next.js ในเว็บที่นำขึ้นใช้งาน

ฐานข้อมูลและบัญชีสมาชิกใช้ Supabase PostgreSQL/Auth และ Deploy บน Vercel Python runtime แล้ว

**เว็บ:** https://alyzyus.vercel.app · **ฉาก 3D:** https://alyzyus.vercel.app/simulation

เอกสารนำเสนออยู่ใน `portfolio/`: [ใบแนะนำโครงการ PDF](portfolio/Alyzyus_Introduction.pdf), [สไลด์แก้ไขได้](portfolio/Alyzyus_Portfolio.pptx), [สไลด์ PDF](portfolio/Alyzyus_Presentation.pdf) พร้อม [บทพูด](docs/PRESENTATION_NOTES.md)

**โครงการสำหรับ Portfolio:** Mr. Wirun Earmvorakul มุ่งศึกษาสาขาวิศวกรรมซอฟต์แวร์ คณะวิศวกรรมศาสตร์ มหาวิทยาลัยเกษตรศาสตร์ ดูขอบเขตผลงาน วิธีสาธิต และคำอธิบายการพัฒนาร่วมกับ AI ใน [คู่มือพอร์ต](docs/PORTFOLIO_GUIDE.md)

Repository นี้เป็น Public ตามที่เจ้าของยืนยัน โดยไม่รวมคีย์ลับหรือข้อมูลลูกค้า ข้อมูล seed ตัวอย่าง 8 รายการกำหนดค่าเริ่มต้นเป็น draft และสต็อก 0 วิธีจ่ายที่เปิดใช้อยู่คือเก็บเงินปลายทาง การรับเงินจริงผ่านบัตร PromptPay และธนาคารต้องตั้งค่าบัญชีร้านก่อน

## ใช้งานในเครื่อง

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
# กรอกค่าใน .env จากบัญชีของเจ้าของร้าน ไม่เผยแพร่ไฟล์นี้
python app.py
```

หากยังไม่ได้ตั้งค่า Supabase เว็บจะแสดงโหมดตัวอย่างอย่างชัดเจน สามารถดูสินค้า ค้นหา บันทึกรายการโปรด และจัดถุงได้ แต่ไม่สร้างคำสั่งซื้อหรือรับเงินจริง ข้อมูลตัวอย่างไม่ใช่สินค้าพร้อมขายจริง

## สิ่งที่มีในระบบ

- หน้าร้านและหน้าสินค้า พร้อมคอลเลกชัน ค้นหา กรอง เรียงราคา และรายการโปรด
- ถุงสินค้า ปรับจำนวน จำข้อมูลในเบราว์เซอร์ และแสดงค่าจัดส่งโดยประมาณ
- สมัครสมาชิก เข้าสู่ระบบ ออกจากระบบ และรีเซ็ตรหัสผ่านผ่าน Supabase Auth
- เช็กเอาต์ด้วยบัญชีสมาชิก โดยเซิร์ฟเวอร์ตรวจราคา คูปอง จำนวนสินค้า และสต็อกอีกครั้ง
- สร้างคำสั่งซื้อและตัดสต็อกในธุรกรรมเดียว ป้องกันกดสั่งซ้ำด้วย idempotency key
- รองรับเก็บเงินปลายทาง โอนธนาคาร บัตร และ PromptPay ผ่าน Stripe ตามค่าที่ตั้งไว้
- ตรวจสถานะการชำระเงินจาก webhook ที่ตรวจลายเซ็น ไม่ใช้ค่าจาก URL เป็นหลักฐานการจ่าย
- ประวัติคำสั่งซื้อส่วนตัว พร้อมผู้ให้บริการขนส่งและเลขพัสดุ
- หลังบ้านสำหรับสินค้า 3 ภาษา สต็อก ราคา รูปภาพ คำสั่งซื้อ การจัดส่ง และตรวจยอดโอน
- อัปโหลด JPG PNG WebP จากเครื่องพร้อมย่อเป็น WebP และเลือกภาพหลัก เก็บใน Supabase Storage โดย API ตรวจสิทธิ์ Admin
- กรอกชื่อและรายละเอียดภาษาหลักครั้งเดียว แปลอีกสองภาษาผ่าน MyMemory พร้อมแท็บตรวจแก้และทางเลือกกรอกคำแปลเอง
- ภาษาไทย อังกฤษ จีน และธีม Light/Dark ที่จำค่าที่เลือก
- อินโทรสั้น กดข้ามได้ แสดงครั้งเดียวต่อ browser session และรองรับ reduced motion
- ดีไซน์ปรับตามหน้าจอ มีฟอร์มที่มี label การใช้งานคีย์บอร์ด และ dialog แบบ native

## โครงสร้างหลัก

```text
app.py                    Flask entrypoint และ page routes
server/                   Supabase, auth, validation และ commerce API
templates/                HTML/Jinja2
public/static/css/        UI ของหน้าร้าน ลูกค้า และหลังบ้าน
public/static/js/         JavaScript ฝั่ง browser ไม่ต้อง build
public/static/images/     ภาพหลักและ favicon
public/static/queue3d.html แบบจำลอง 3 มิติ HTML ไฟล์เดียว
data/demo-products.json   ข้อมูลสาธิต ไม่มีข้อมูลลูกค้าจริง
supabase/migrations/      ตาราง RLS และ transactional functions
supabase/seed.sql         สินค้าตัวอย่างในสถานะ draft ไม่เปิดขาย
supabase/OPERATIONS.md    ขั้นตอนฐานข้อมูลและข้อกำหนดการรับเงินจริง
tests/                    การตรวจ backend และ PostgreSQL
legacy/                   เก็บโค้ดเดิมไว้ ไม่ส่งขึ้น Vercel
```

ไฟล์ข้อมูลเดิมเก็บไว้ใน `legacy/private/tasks.json` และ `legacy/private/users.json` ไม่ถูกนำเข้า Supabase อัตโนมัติ ไม่ส่งขึ้น deployment และไม่ใช้ระบบรหัสผ่านแบบเดิมอีกต่อไป

## ตั้งค่า Supabase

1. โปรเจกต์ร้านที่เชื่อมแล้วคือ `lfidojbygahcywofdkef` (Alyzyus) อยู่ในภูมิภาค Mumbai `ap-south-1`; deployment ล่าสุดใช้ Vercel region `bom1`
2. ใช้ migration ทุกไฟล์ใน `supabase/migrations/` ตามลำดับชื่อไฟล์ ผ่าน SQL Editor หรือ Supabase CLI
3. ถ้าต้องการสินค้า draft ให้รัน `supabase/seed.sql` ข้อมูลเริ่มต้นเป็นสต็อก 0 และยังไม่เผยแพร่
4. ตั้งค่าตัวแปรตาม `.env.example` โดยเก็บ service role key เฉพาะฝั่งเซิร์ฟเวอร์
5. ตั้งค่า Site URL และ redirect URLs ใน Supabase Authentication ให้ตรงกับโดเมนจริง
6. สมัครบัญชีเจ้าของร้าน แล้วให้ role `admin` ผ่าน SQL ที่เชื่อถือได้ตามคู่มือ OPERATIONS ห้ามรับ role จากฟอร์มสมัครสมาชิก
7. ตั้ง SMTP สำหรับอีเมลยืนยัน/กู้รหัสผ่านในระบบจริง และทดสอบอีเมลถึงปลายทาง

RLS ปิดการอ่านคำสั่งซื้อของคนอื่น และผู้ใช้ทั่วไปเปลี่ยนสิทธิ์ตัวเองเป็น admin ไม่ได้

## วิธีชำระเงิน

| วิธี | การตั้งค่า | ยืนยันชำระเงิน |
|---|---|---|
| เก็บเงินปลายทาง | เปิด COD ใน environment | ผู้ดูแลยืนยันเมื่อรับเงินจริง |
| โอนธนาคาร | ชื่อธนาคาร ชื่อบัญชี เลขบัญชี | ผู้ดูแลตรวจยอดก่อนกดชำระแล้ว |
| บัตร/กระเป๋าเงินที่รองรับ | Stripe key, webhook และ payment configuration | webhook จาก Stripe |
| PromptPay | เปิดใน Stripe และตั้ง payment configuration ของ PromptPay | webhook จาก Stripe |

การรองรับในโค้ดไม่เท่ากับบัญชีผู้ให้บริการเปิดรับเงินจริงแล้ว ต้องใช้บัญชีร้านที่ผ่านการตรวจสอบ เปิดวิธีจ่าย และทดสอบครบก่อนใช้ live keys การคืนเงินผ่านผู้ให้บริการต้องดำเนินการและกระทบยอดตามคู่มือ ไม่คืนเงินอัตโนมัติเมื่อเปลี่ยนสถานะคำสั่งซื้อ

ค่าจัดส่งที่ตั้งไว้: 80 บาท ส่งฟรีเมื่อยอดสินค้าก่อนส่วนลดถึง 2,500 บาท สำหรับที่อยู่ในประเทศไทย คูปองเริ่มต้น `WELCOME10` ลด 10% สำหรับออเดอร์แรกที่มีสิทธิ์ ควรปรับให้ตรงนโยบายร้านก่อนเปิดขาย

## Deploy บน Vercel

Vercel รองรับ Flask จาก `app.py` โดยตรง ไม่ต้องมี frontend build ตั้งค่าตัวแปรจาก `.env.example` ใน project environment และตั้ง URL ของร้านให้ตรงกับ deployment

```powershell
npx vercel
npx vercel --prod
```

ตรวจหน้าเว็บ, `/api/health`, การสมัคร/เข้าสู่ระบบ, RLS, ออเดอร์, การตัดสต็อก, webhook, การจัดส่ง และอีเมลจริงในโปรเจกต์ทดสอบก่อนเปิดขาย สคริปต์ `scripts/package-vercel.py` ใช้ allowlist เพื่อไม่อัปโหลดข้อมูลลูกค้า รหัสผ่านเดิม หรือ secret

## รายการที่เจ้าของร้านต้องเติมก่อนเปิดขาย

- รูป รายละเอียด ราคา สต็อก และหมวดหมู่ของสินค้าจริง
- บัญชีรับเงิน Stripe/ธนาคาร และการทดสอบรับเงิน/คืนเงิน
- ข้อมูลติดต่อผู้ขาย ระยะเวลาจัดส่ง เงื่อนไขคืนสินค้า และนโยบายร้านฉบับจริง
- โดเมน, SMTP, redirect URLs, ผู้ดูแลร้าน และแผนสำรอง/กู้ข้อมูล

รูปสินค้าสาธิตใช้เพื่อแสดง UX เท่านั้น ดูที่มาและ prompt ภาพหลักใน `ASSETS.md`

## แบบจำลอง 3 มิติ

เปิด `public/static/queue3d.html` ได้โดยตรง หรือไปที่ `/simulation` ในเว็บ ไม่ต้องติดตั้งไลบรารีเพื่อเปิดไฟล์ ใช้ Three.js จาก cdnjs และฟอนต์ Google Fonts จึงต้องเชื่อมอินเทอร์เน็ต

โหมดสำนักงานมีครบ 5 จุดบริการ อัตรานักศึกษาแบบ Poisson เจ้าหน้าที่ตรวจเอกสาร/อาจารย์ที่ปรับจำนวนได้ แถบความเร็ว กล้องหมุน/ซูมด้วย pointer events และการเริ่มวันใหม่

โหมดสินค้า `/simulation?mode=product` แสดงตัวอย่างกระบวนการ ส่วน `/simulation?mode=product&order=<UUID>` แสดงสถานะจากคำสั่งซื้อที่บัญชีปัจจุบันมีสิทธิ์อ่าน ไม่ใช่ตำแหน่ง GPS ของพัสดุ และไม่เปลี่ยนสถานะจริงตามเวลาจำลอง

พารามิเตอร์รวมอยู่ที่ `PARAMETERS` ต้นสคริปต์ วาดตัวละครไม่เกิน 80 ตัวพร้อมกัน แต่จำนวนคนในคิวคำนวณจากข้อมูลจำลองทั้งหมด จำกัดสำนักงาน 30 FPS และเส้นทางสินค้า 18 FPS/ความละเอียดจอ พักเมื่อฉากพ้นหน้าจอหรือแท็บถูกซ่อน และปิดการเคลื่อนไหวเริ่มต้นเมื่อผู้ใช้ตั้ง reduced motion

## รูปภาพและคำแปลสำหรับผู้ดูแล

เลือกภาษาหลัก กรอกชื่อกับรายละเอียด แล้วกดแปลหรือบันทึก ระบบจะแปลภาษาที่ยังไม่มีหรือสร้างคำแปลใหม่เมื่อแก้ต้นฉบับ เปิดแท็บภาษาเพื่อตรวจแก้ก่อนวางขาย ถ้าบริการแปลไม่พร้อมหรือโควตาหมด ระบบรักษาข้อมูลที่กรอกไว้ ปิดตัวเลือกแปลอัตโนมัติแล้วกรอกคำแปลเองได้ ระบบส่งเฉพาะชื่อและรายละเอียดสินค้าไปยัง [MyMemory API](https://mymemory.translated.net/doc/spec.php) ไม่ส่งข้อมูลลูกค้าหรือข้อมูลบัญชี

อัปโหลดภาพได้สูงสุด 10 รูป โดยเลือก JPG PNG WebP ต้นฉบับไม่เกิน 12 MB ต่อรูป เบราว์เซอร์ย่อทีละไฟล์ จากนั้นเซิร์ฟเวอร์ตรวจชนิดภาพจริง ลบ metadata และสร้าง WebP ขนาดไม่เกิน 1600 พิกเซล เก็บใน public bucket `product-images` ของ Supabase Storage ภาพสินค้าเป็นข้อมูลสาธารณะ ส่วนการอัปโหลดต้องเป็น Admin ภาพแรกใช้เป็นภาพหลัก กดปุ่มเลือกภาพหลักหรือนำออกได้ การนำภาพออกจากสินค้าจะไม่ลบไฟล์ใน Storage เพื่อรักษาภาพที่อาจมีออเดอร์เดิมใช้อยู่

ถ้ามีรูปออนไลน์อยู่แล้ว วาง URL ไฟล์รูปโดยตรง เช่น `https://example.com/product.jpg` ทีละบรรทัด หรือใช้ `/static/images/product.webp` สำหรับรูปในเว็บไซต์ ไม่ใช้ลิงก์หน้าเว็บขายสินค้า SVG และ GIF ไม่รับผ่านช่องอัปโหลด

## แอปบนอุปกรณ์และการปรับหน้าตา

เปิด `/install` เพื่อดูวิธีติดตั้ง Alyzyus แบบ PWA บนเบราว์เซอร์ที่รองรับ มีปุ่มสมัครสมาชิกแสดงชัดในส่วนหัวและหน้าแรก ใช้ `/account?mode=signup` ไปหน้าสมัครโดยตรง รองรับหน้าเว็บตั้งแต่จอแคบ 280px จนถึงแท็บเล็ตและเดสก์ท็อป การติดตั้งบน Android, iOS/iPadOS และ macOS ขึ้นกับเบราว์เซอร์/เวอร์ชัน ส่วนโทรศัพท์ปุ่มกดที่เบราว์เซอร์ไม่รองรับให้ใช้งานผ่านเว็บตามความสามารถของอุปกรณ์ อ่านรายละเอียดและขั้นตอนเตรียมส่ง Store ใน `docs/MOBILE_APP.md` โครงการนี้ยังไม่ได้เผยแพร่ผ่าน App Store หรือ Play Store

ปุ่ม **ปรับหน้าตา** ให้เลือกโทนสี 6 แบบ, สว่าง/มืด/ตามอุปกรณ์, ตัวอักษรอ่านสบาย และเปิด/ปิดการเคลื่อนไหว เลือก JPEG/PNG/WebP เป็นพื้นหลังได้ ระบบย่อภาพและเก็บไว้ใน IndexedDB ของอุปกรณ์นั้นเท่านั้น ไม่อัปโหลดรูปส่วนตัวไป Supabase และไม่ซิงก์ไปเครื่องอื่น หากเบราว์เซอร์ล้างข้อมูลหรือใช้โหมดส่วนตัว การตั้งค่าอาจไม่คงอยู่ รูปพื้นหลังไม่ทำให้พื้นผิวข้อความโปร่งจนอ่านยาก

Service Worker เก็บเฉพาะไอคอนสาธารณะกับหน้าออฟไลน์ทั่วไป ไม่เก็บ API, ข้อมูลบัญชี, ออเดอร์, หน้า Admin, หน้าชำระเงิน หรือ HTML ของร้านไว้ใช้ออฟไลน์ การสั่งซื้อและดูข้อมูลจริงต้องเชื่อมอินเทอร์เน็ตเสมอ

## ประวัติกิจกรรม

หน้า `/admin/logs` โหลดบันทึกผ่าน API ที่ตรวจสิทธิ์ Admin และ RLS อีกชั้น บันทึกสินค้า สต็อก และการเปลี่ยนสถานะคำสั่งซื้อจากฐานข้อมูล รวมทั้งกิจกรรมบัญชีที่เซิร์ฟเวอร์ยืนยันแล้ว ไม่เก็บรหัสผ่าน โทเคน ข้อมูลบัตร หรือที่อยู่ลูกค้า ไม่สร้างประวัติย้อนหลังที่ไม่มีหลักฐาน อ่านการจัดเก็บและการดูแลใน `docs/ACTIVITY_LOGS.md`

GitHub Actions ใน `.github/workflows/checks.yml` ตรวจ Python, JavaScript, ธุรกรรม/RLS และสัญญา PWA โดยไม่ใช้คีย์ Production การอัปโหลด GitHub กับการเชื่อม Vercel เพื่อ Deploy อัตโนมัติเป็นคนละการตั้งค่า


## ศูนย์ช่วยเหลือลูกค้า

เปิด `/support` เพื่อส่งคำร้อง ติดตามสถานะ และสนทนาในเรื่องเดิม ลูกค้าต้องเข้าสู่ระบบและยืนยันอีเมลก่อนใช้งาน ข้อมูลคำร้องอ่านได้เฉพาะเจ้าของเรื่องกับผู้ดูแลร้าน Admin ใช้ `/admin/support` ตอบและจัดการสถานะ ไม่มีการตอบข้อความแทนเจ้าหน้าที่ ไม่มีการส่งอีเมลหรือข้อความออกบริการภายนอก และไม่มีการอ้างว่าเจ้าหน้าที่ออนไลน์อยู่ รายละเอียด API และข้อจำกัดอยู่ใน `docs/CUSTOMER_SERVICE.md`

ตัวเลือก **แต่งแอป** ใช้ได้เฉพาะบัญชีที่เข้าสู่ระบบและยืนยันอีเมล เซิร์ฟเวอร์ตรวจสิทธิ์ผ่าน `/api/account/appearance` ก่อนเปิดตัวเลือก การตั้งค่าและรูปพื้นหลังเก็บเฉพาะเครื่องโดยแยกตามบัญชี เมื่อออกจากระบบจะนำสีและพื้นหลังส่วนตัวออกจากหน้าจอ ผู้ที่ยังไม่เข้าสู่ระบบยังเลือกภาษาและธีมสว่าง/มืดพื้นฐานได้เพื่อความสะดวกในการอ่าน


การแต่งแอปรุ่นสมาชิกใช้ key `alyzyus-appearance-member-v2:<UUID>` และรูป `wallpaper:<UUID>` ใน IndexedDB ข้อมูลเก่ารุ่นที่ยังไม่ผูกบัญชีจะไม่ถูกนำมาใช้กับบัญชีใดโดยอัตโนมัติ จึงอาจต้องเลือกสีหรือรูปใหม่ครั้งแรก ข้อมูลส่วนตัวไม่ถูกลบเมื่อออกจากระบบ แต่จะไม่แสดงจนกว่าจะตรวจบัญชีเดิมสำเร็จอีกครั้ง
